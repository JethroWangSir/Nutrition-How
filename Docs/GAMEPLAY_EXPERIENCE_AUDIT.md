# 第五階段：遊戲體驗與內容品質稽核

稽核日期：2026-10-12  
範圍：開場、主選單、知識頁、教學、四個關卡、結局、鍵盤／滑鼠／搖桿操作。

## 優先級定義

- P0：阻止玩家完成流程或造成資料損失。
- P1：功能看似存在但無效，或常見操作造成明顯困惑。
- P2：一致性、可讀性與操作回饋問題。
- P3：可選的品質提升。

## 首輪結果

| 優先級 | 項目 | 現況 | 處理方向 |
| --- | --- | --- | --- |
| P1 | 主音量控制 | Slider 已接到 `SetVolume`，但 Mixer 設定程式被註解，且 Slider 預設關閉、沒有入口 | 第一批修正：開始畫面提供音量控制，實際套用 `MasterVolume` 並使用 PlayerPrefs 保存 |
| P1 | 設定持久化 | 音量每次啟動回到預設值 | 第一批修正：啟動時還原 Slider 與 Audio Mixer |
| P1 | 暫停選單元件查找 | 依賴 `GameObject.Find`；物件未啟用時可能找不到 | 第一批修正：直接使用 Scene 已序列化的參照並加上空值防護 |
| P1 | 進度保存定義 | 四關完成狀態只存在記憶體，結局後全部清除 | 先確認要保存「已通關關卡」或只保存「本輪收集進度」，再實作 |
| P2 | 操作提示 | 教學以 Windows 鍵盤圖示為主，尚未系統性核對搖桿與 Mac 顯示 | 第二批逐頁核對實際 Input Actions |
| P2 | 暫停一致性 | 關卡、影片與對話各自控制暫停，缺少單一狀態來源 | 第二批統一暫停規則並增加失焦／控制器中斷測試 |
| P2 | 文字與按鈕一致性 | 返回、主選單、跳過、重新開始分散在不同 Scene | 第二批建立詞彙與行為對照表後統一 |
| P3 | 遊戲回饋與難度 | 尚未建立移動、受傷、Boss、倒數時間等可比較基準 | 第三批先量測再調整，避免憑感覺全面改數值 |

## 第一批完成條件

- 音量 Slider 會即時改變 `MainMixer/MasterVolume`。
- 音量限制於 -80 dB 至 0 dB，重新啟動後維持設定。
- 暫停、恢復、重新開始與返回主選單不因 UI 初始狀態而拋出例外。
- 原有全部流程測試與新增設定測試通過。

## 第一批驗證結果

- PlayMode：14/14 通過，包含新增的音量限制與 PlayerPrefs 持久化測試。
- 視覺回歸：1024×768、1280×800、1920×1080 各 23 個場景，共 69 張通過。
- 三種解析度的開始畫面皆可看到右上角音量控制，未遮住 Logo、離開按鈕或安全區。
- 三份 Development Player log 均無 Exception、Error、Assertion 或 Crash。
- LZ4HC Release Build 成功：398 MB、`arm64`、Bundle ID 與 App 名稱正確，簽章結構通過。

## 後續順序

1. 完成第一批設定／暫停基礎修正與 Release 驗證。
2. 核對每張教學頁與 Input Actions，統一操作提示。
3. 統一關卡失敗、重試、暫停及返回行為。
4. 決定長期進度的產品規則後再加入存檔，避免錯存本輪臨時狀態。
5. 最後進行關卡難度、回饋、音訊平衡與文字校對。
